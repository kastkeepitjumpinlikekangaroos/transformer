Setup

From zero to a running pipeline

You'll install Java, build the jar, and run the jaffle-shop example: a port of dbt Labs' reference project with 6 CSV sources, 15 tables, and 26 data-quality tests over about 150k rows. It takes about 10 minutes, and most of that is the first build.

Install Java 21

Java is the only thing transformer needs at runtime. It's built and tested on Java 21 (LTS). A JDK or a JRE will do.

PlatformInstall
macOSbrew install openjdk@21
Debian / Ubuntusudo apt install openjdk-21-jre-headless
WindowsInstall Eclipse Temurin 21 from adoptium.net
 
$ java -version
openjdk version "21.0.6" 2025-01-21 LTS

The headless run command works on any OS with Java 21. The desktop GUI bundles JavaFX for macOS on Apple Silicon and Windows. On Linux, use the CLI.

Build the jar

transformer builds with Bazel. Install Bazelisk (brew install bazelisk on macOS), which picks up the Bazel version pinned in the repo. Bazel downloads its own JDK and every library it needs. 

$ git clone https://github.com/kastkeepitjumpinlikekangaroos/transformer.git
$ cd transformer
$ bazel build //:transformer_deploy.jar
$ cp bazel-bin/transformer_deploy.jar transformer.jar

transformer.jar is self-contained: the SQL engine, the CSV and Parquet readers and writers, and the GUI are all inside. Copy it to any machine with Java 21 and it runs there.

Run the jaffle-shop example

The example lives in examples/jaffle_shop/job. Run it headless: 

$ java -Xmx2g -jar transformer.jar run examples/jaffle_shop/job \
    --output /tmp/jaffle-out --execution-time 2026-01-01T00:00:00Z
Job:            /path/to/transformer/examples/jaffle_shop/job
Execution time: 2026-01-01T00:00:00Z
Inputs:         6

  Succeeded        stg_supplies                 rows=65            783 ms
  Succeeded        stg_customers                rows=935           757 ms

  Succeeded        stg_order_items              rows=90900         234 ms

  Succeeded        customers                    rows=935            50 ms

Job SUCCEEDED (15 Succeeded)

The whole run takes about two seconds. The command exits 0 when every task and validation passes, 1 when anything fails, and 2 when the arguments are wrong. Leave out --output to write to <jobDir>/output, and leave out --execution-time to use the current time.

Each table gets its own output directory, and the run's summary goes in job.json:

/tmp/jaffle-out/
  job.json                 every task's status, rows, timings, failed validations
  customers/
    part-00000.parquet
    _run.json              this task's full run record
  orders/
  stg_orders/
  ...

Query what it wrote

$ java -jar transformer.jar query --job examples/jaffle_shop/job \
    --job-output /tmp/jaffle-out \
    "SELECT customer_type, COUNT(*) AS customers, ROUND(AVG(lifetime_spend), 2) AS avg_spend
     FROM customers GROUP BY customer_type ORDER BY customer_type"
┌───────────────┬───────────┬───────────┐

│ STRING        │    BIGINT │    DOUBLE │

2 rows

transformer query runs SQL from the command line, here over the job's inputs and the tables its run wrote, each by its name. --table orders=data/orders.csv names any CSV or Parquet file instead, with no job at all. Add --format csv or --format json for a script, and --output result.parquet to write the result to a file. With no SQL it opens a shell, where .tables lists what you can query.

Open it in the GUI

$ java -jar transformer.jar gui examples/jaffle_shop/job

The GUI draws the DAG of inputs and tables. Set the execution time and output directory, then press Run (Cmd/Ctrl+R) to watch each task go from queued to running to done. Double-click a table to preview its rows, open its validations, or query any output from the SQL console and chart what it returns. Use the run picker to reopen a previous run exactly as it finished. Every SQL editor highlights syntax and takes vim's keys; View → Vim Keybindings turns them off. File → New Project starts an empty project, and the Add Input and Add Table menus create the directories for you.

Explore what it wrote

$ bazel build //:transformer_viewer_deploy.jar
$ java -jar bazel-bin/transformer_viewer_deploy.jar /tmp/jaffle-out

The data viewer is a jar of its own for the data your jobs wrote. Open it on a folder of job outputs, here the run above: each job's output is a dataset. A query tab runs SQL over every table, each named <dataset>__<table>, such as jaffle_out__customers, in the same editor as the GUI, and its Chart tab draws the result as a bar, line, area, scatter or pie chart, which Save PNG writes to a file. Click a table in the list to inspect it: its first rows, its columns, what its run recorded (its SQL, validations and timings), and its lineage, how it was made from the other tables, within a job and across jobs when one job reads another's output.

Read the project

The project is ordinary files. An input is one JSON config, and relative paths resolve against the job directory:

inputs/raw_orders/config.json

{ "path": "data/raw_orders.csv" }

A table is one SELECT. The directory name is the table name that other queries refer to:

tables/stg_orders/main.sql

SELECT
  id          AS order_id,
  store_id    AS location_id,
  customer    AS customer_id,
  subtotal    AS subtotal_cents,
  tax_paid    AS tax_paid_cents,
  order_total AS order_total_cents,
  CAST(order_total AS DOUBLE) / 100 AS order_total,
  ordered_at
FROM raw_orders

Downstream tables just reference upstream ones. The orders table joins stg_orders to order_items_summary, and transformer waits for both before running it. An optional output.json sets the format or a per-run partition:

tables/orders/output.json

{ "format": "parquet" }

tables/customers/validations/customer_type_accepted_values.sql

-- A validation passes when it returns zero rows.
SELECT customer_id, customer_type
FROM customers
WHERE customer_type NOT IN ('new', 'returning')

Time variables work in SQL and paths alike. '{{ today }}' AS exec_date in customers/main.sql becomes '20260101' for the run above.

Break it on purpose

To see what a failure looks like, change 'returning' to 'repeat' in tables/customers/main.sql and run again: 

  ValidationFailed customers                    rows=935            55 ms
    validation 'customer_type_accepted_values' returned 929 row(s)

Job FAILED (1 ValidationFailed, 14 Succeeded)

The table is still written, so you can inspect it. A sample of the failing rows lands in customers/_validation-customer_type_accepted_values.csv, and any table downstream of a failed one is skipped. Revert the edit and the job passes again.

Start your own project

Copy examples/jaffle_shop/job, or use File → New Project in the GUI. Then point your inputs at your own CSV or Parquet files, either a single file or a glob such as /data/events/*.parquet. If you work with a coding agent, give it the job directory and the commands on this page: 

This is a transformer project (examples/jaffle_shop/job is a reference).
Inputs live in inputs/<name>/config.json, tables in tables/<name>/main.sql,
tests in tables/<name>/validations/*.sql (pass = zero rows).
Run with: java -jar transformer.jar run <jobDir> --output <dir>
It exits 0 only when everything passes; failures are in <dir>/job.json.

The README covers the full SQL surface, CSV and Parquet options, templating variables, and run records.
